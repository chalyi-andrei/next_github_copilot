# CLAUDE.md

## Процесс разработки по умолчанию: planner → developer → tester

Инструкция для главного агента. Если ты субагент `planner`, `developer` или `tester` — пропусти этот раздел и следуй своей роли.

- Для каждой задачи, которая меняет код (новая функциональность, исправление бага, рефакторинг), по умолчанию используй skill `orchestrate`.
- Порядок:
  1. Запусти субагента `planner`: он изучает код и составляет план с критериями приёмки `AC-*`.
  2. Передай план дословно субагенту `developer` для реализации.
  3. Запусти субагента `tester` для проверки. Он возвращает `VERDICT: PASS` или `VERDICT: FAIL`.
  4. При `FAIL` верни найденные проблемы тому же `developer` на исправление и снова запусти `tester`.
- Повторяй цикл до `PASS`, но не больше 3 раундов. Один раунд — это работа `developer` плюс проверка `tester`. Если после 3-го раунда всё ещё `FAIL`, остановись и сообщи пользователю итог и нерешённые проблемы.
- Не пропускай этапы и не пиши продуктовый код сам, пока идёт оркестрация.
- Без оркестрации можно: отвечать на вопросы о коде, делать правки в 1–2 строки и выполнять явные просьбы пользователя сделать что-то самому.

## Объявление этапов оркестрации

Для задач с изменением кода используй skill `orchestrate` и объявляй пользователю каждый этап дословно этими фразами:

1. Перед стартом: «Запускаю orchestrate»
2. Перед запуском planner: «Запускаю planner — анализирую задачу и составляю план»
3. Перед запуском developer: «Запускаю developer — реализую изменения»
4. Перед запуском tester: «Запускаю tester — проверяю изменения»
5. Если tester вернул `VERDICT: FAIL` и лимит раундов не исчерпан: «Tester нашёл ошибки. Возвращаю задачу developer на исправление». Затем снова «Запускаю tester — проверяю изменения».

Шаги 4–5 повторяются, всего не больше 3 раундов.

В конце обязательно сообщи:
- **Статус:** `PASS` или `FAIL`, и в каком раунде из 3 он получен;
- **Что поменял:** список изменённых и созданных файлов с кратким описанием изменений;
- **Какие проверки прогнал:** lint, tsc, build, тесты и результат каждой по последнему отчёту tester;
- при `FAIL` — какие проблемы остались нерешёнными.
